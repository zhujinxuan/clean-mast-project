# 12 — Representative-year consumption after redesign

**Type:** grilling

**Status:** resolved

**Blocked by:** 05-method-registry-v1

## Question

Decide what representative-year calibration consumes from the redesigned reconstruction system.

Julia status quo (memory `core://agent/4`): rep-year calibration exists only in Julia — `Core.calibrate_to_representative_year` (2% threshold year selection), `apply_calibration` uses per-sector slopes from the 16-sector fit, no intercept. The 16-sector fit is trained but never used for reconstruction — dead weight except for rep-year.

Decide:

1. **Slope source**: keep Julia semantics — a deliberately-trained 16-sector fit feeding per-sector slopes — or re-derive calibration from the winning reconstruction method/fit?
2. **Calibration operator shape**: is rep-year calibration itself a method under the fit→predict contract (fit = slopes, predict = calibrated series), or a separate transform?
3. **Python gap**: Python currently has only config IR + on-the-fly report statistics (no calibrated series output) — what does the migrated version produce and persist?
4. **Migration semantics fidelity**: 2% threshold, no-intercept slope application — preserved as-is, or revisited while we're here?

## Answer

Decided 2026-09-02, user-confirmed (grilling + research tickets 17/18):

1. **Registry shape (Q2′).** Rep-year calibration is a registry method under a third scope `repyear` (scope vocabulary {horizontal, vertical} → +{repyear}; CONTEXT.md amended). v1 id `repyear.ws.sectorized-delta`; sensor-type segment ws-only. Follows the fit→predict contract: fit = slope-source ref + per-sector deltas + params; predict = the additive delta transform. Artifact + cache per ticket 10's envelope; cache key = (repyear method, slope-source ref, rep-year window, config hash).
2. **Slope source (Q1′).** Slope provenance is a property of each `repyear.*` method, not of the phase. v1 consumes `horizontal.ws.ols-16sector` slopes by identity — cache hit when reconstruction already trained the same key, train-on-demand otherwise. Future methods declare their own provenance: a VR-based variant would consume `horizontal.ws.variance-ratio` (global ratio, global delta); the 行标 two-stage is self-trained (mast-direction binning, global delta) — a `repyear.*` fit payload carries `consumes: <horizontal fit key>` XOR embedded self-trained slopes. Additive ids only.
3. **Semantics (Q3, reshaped by ticket 17 research, user-confirmed).** Additive per-sector delta × slope kept (GB/T 18710 Appendix A algebra). **Anchor = climatology (complete-years) meso mean, per sector, sectored by meso direction** — delta[sector] = climatology_mean[sector] − training-overlap_mean[sector]. Julia's actual-year selection is deleted: no standard/tool selects a real year, GB/T 18710 anchors at the multi-year mean, and the latest-qualifying-year rule was CleanMast-local. Consequently **no year selection and no no-qualifying-year failure mode exist**. Need-check = 2% trigger (|climatology − training-overlap mean| / climatology > 2%; documented analog NB/T 31147 §5.2). Clamp [0.5, 25] kept. `threshold` and clamp bounds are required config params (no optionals). Actual-year mode → map backlog (Not-yet-specified).
4. **Benchmarking (Q4, per ticket 18 research).** No calibration benchmark in v1 — one method, nothing to select; overlap length and seasonal coverage dominate error. MEASNET §8.3.2 in-sample diagnostics (MBE/MAE/RMSE of the calibration fit) logged, no gate. The documented hold-out pseudo-campaign exam (ticket 18 comments) is the design for the day a second `repyear.*` method registers.
5. **Short-mast policy (Q4 Part 2, user).** No refusal tiers, no automatic correlation gates — **config decides** whether calibration runs. Native overlap length and correlation are recorded in the fit artifact as informational diagnostics, never gates. **The only skip path is the need-check** (≤2% → `rep-year-skipped`). **Calibration window = exactly one year** — the best-coverage one-year window within the reconstructed extent (ticket 04's coverage-driven rule), matching the 规范 代表年 hourly dataset. Multi-year calibrated series is not a tool feature: multiple one-year runs over multiple ranges via a Justfile DAG when genuinely needed (rare).
6. **Production shape (Q5).** Calibrated WS series as the rep-year phase output parquet. Provenance flags: `rep-year` appended to calibrated cells, `rep-year-skipped` to exactly the cells that would have been calibrated when the need-check fails — the flags column is a modification log only; confidence evidence (tier facts, overlap length, correlation) lives in the fit artifact + provenance manifest.
7. **Coverage (Q6).** Rep-year requires a meso reconstruction set for the mast; a cross-only mast with rep-year configured = config-load validation error (ERA5 coverage ⇒ no legitimate no-meso case; always a config bug).
