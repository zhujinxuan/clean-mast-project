# Reconstruct Migration — Wayfinding Map

## Destination

Decision-complete design for migrating wind-data reconstruction from Julia (`CleanMastProject/`, frozen, maintenance mode) to `packages/cleanmast`, replacing ad-hoc method selection with a benchmarked protocol. Pipeline per standard: data clean → reconstruct-single → reconstruct-cross → reconstruct-meso → representative-year calibration; fill-heights runs after meso and after rep-year, unified into the same fit→predict contract. Done = every decision ticket resolved and the way to implementation is clear; this map ships decisions, not code.

## Decisions so far

- [01 — Charting decisions](issues/01-charting-decisions.md) — naming (method/fit/predict/fill), fill-heights unified into the contract, monthly blocked bootstrap, ε-group RMSE sort (ε=0.05), vertical 2×2 method families (WS/WD × interp/extrap), train-on-demand + fit cache, benchmark recommends but run-config strategy per reconstruction set decides, production fits always retrain on full data. **Amended 2026-09-01**: screen runs in the benchmark commands, not recommend; blocked subsampling is the single protocol (whole-series path removed) — see ticket 01 `## Amendments`.
- [02 — Research: MCP benchmarking practice](issues/02-research-mcp-benchmarking.md) — charted protocol evidence-aligned (contiguous monthly blocks, 12-month/90% whole-series norm, WS-RMSE+bias-secondary, no dominant MCP method); two flagged tensions: ≥90% availability gate stricter than gap-impact evidence (FGW 80% option), 16-sector ≥5-point fallback vs literature ≥20-per-bin precedent.
- [03 — Research: vertical shear validation practice](issues/03-research-shear-validation.md) — hold-out-layer exam is MEASNET-sanctioned "vertical cross-prediction"; WS matrix trimmed 20→16 (drop day scale, keep all 4 layer schemes); law-family (power vs log) flagged as a missing method dimension; WD = {global, per-sector} × {1h, month, whole-series} circular offsets with wrapped-MAE; interpolation = log-linear default + two-point power-law competitor, per-interval params, spot-check only.
- [04 — Operator contract and timerange semantics](issues/04-operator-contract-timerange.md) — partial-series predict; mast entity = one contiguous span (two files → two entities, no naming convention, no site concept); strict-intersection fill; per-mast working windows with explicitly-chosen long meso window and coverage-driven rep-year window; provenance = append-only `{sensor}_flags` columns (minted at clean stage) + per-run span manifest, replacing Julia's dead sidecar CSV; config carries fit identity only (parameters live in the artifact); two reference modes (identity default, explicit-artifact for ad-hoc transfers).
- [05 — Method registry v1](issues/05-method-registry-v1.md) — id grammar `<scope>.<sensor-type>.<algorithm>[.<variant>]` (scopes horizontal/vertical; law/layers/time-scale as explicit id segments; add-only); stateless `MethodSpec` registry — `MethodId` StrEnum + per-method params/fit-payload models in `shared/reconstruction/`, pure fit/predict functions in dataprocessing; v1 = 3 WS + 2 WD horizontal + 4 vertical families, power-law only (log-law out — not in Chinese 规范); 16-sector keeps both lives (benchmarkable + rep-year slopes), rep-year reuses its fit via the deterministic cache, `min_points_per_sector` default 20 / parity override 5.
- [06 — Benchmark protocol: cross and meso](issues/06-benchmark-cross-meso.md) — blocked subsampling as the single protocol for all records (whole-series path removed); benchmark is its own phase, two commands (`benchmark-horizontal`/`benchmark-vertical`) with own configs, screen runs inside them, recommend metadata-only and materializes all defaults as required fields; WS-only subsampled pre-rank cut at `top_k` (seeded 5), WD inherits the cut; ε-group sort per sensor type at its own reference height; one winner per mast, no fallback chains; benchmark artifact TOML = screen table + fold metrics + winner summary, fold fits discarded; meso↔mast alignment: train on meso hourly grid (WS mean / WD vector mean), predict at 10-min via up-front meso interpolation, 16-sector by meso WD.
- [11 — Reference-height selection](issues/11-reference-height-selection.md) — reference height per (mast × sensor type): required `ws_reference_height`/`wd_reference_height`, recommend seeds nearest sensor of that type to `reference_height_hint` (default 160; lidar 200m tops vs ≤160m hubs); horizontal-only concept — vertical uses hold-out-layer exams; selection fits at reference height only, full-height training once for the winner; height disagreement accepted, no diagnostics (turbine heights correlate with ~160m reference); Julia priority score dropped.
- [07 — Benchmark: vertical extrapolation](issues/07-benchmark-vertical-extrapolation.md) — one `benchmark-vertical` command, two ceremonies (extrapolation full bootstrap, interpolation middle-layer spot-check); one winner per (mast × sensor type × mode), top-layer-exam ranked, leave-one-out exams as diagnostics; derived per-mast exam plan (runs / not-needed / unbenchmarkable) with family default seeds (`powerlaw.all.series` / `global.series` / `ws.interpolate.powerlaw` / `wd.interpolate.circular`) — interpolation seeds superseded by ticket 08 (`…powerlaw.brackets.10min` / `…linear.brackets.10min`) that still land in strategy config for per-timestamp dropouts; `interpolation_exam_range` seeded [125,160]; four trimmable candidate lists; WD = wrapped-MAE (ws ≥ 3 m/s only, no weighting) ε=2°, independent of WS; routing per timestamp by availability, extrapolation anchored at highest observed layer below target, filled values never anchor, no blend; P90|bias| (90th pct of |fold bias| across folds) recorded as review diagnostic, never in the sort.

- [08 — Vertical interpolation methods](issues/08-vertical-interpolation.md) — interpolation = two 4-scale blend families: `vertical.ws.interpolate.powerlaw.brackets.<10min|1h|month|series>` (two one-sided power-law estimates from the bracketing observed layers, ln-$z$ distance-weighted; `10min` degenerates to the exact two-point power law) and `vertical.wd.interpolate.linear.brackets.<10min|1h|month|series>` (linear-in-$z$ wrapped circular offsets — evidence check killed ln-$z$ for veer: Ekman ≈ linear, KvdL 2023 steeper than ln $z$, MOST zero). Layer scheme `brackets` is an explicit id segment (no silent defaults; `dist-weighted` may enter additively). `10min` variants are fit-free (predict re-derives everything at predict time); `1h`/`month`/`series` train per (adjacent interval × time bucket) shear/veer tables, one fit per (mast × sensor type × method). Loglinear dropped from v1; WD exam upgrades to a real selection; winner per (mast × sensor type × interpolate) from the middle-layer spot-check pooled over folds × layers; default seeds `…powerlaw.brackets.10min` / `…linear.brackets.10min`. **Amends tickets 05/07** (registry ids, candidate lists, seeds).
