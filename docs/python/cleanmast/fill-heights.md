# fill-heights 高度填充命令

## 概述

fill-heights 是 CleanMast 中用于风速和风向高度外推与插值的核心命令。该命令能够根据已有的测量层数据，推算出缺失高度层的数据值，是风资源评估数据处理流程中的重要环节。

在实际的风电场测风工作中，由于成本和技术限制，不可能无限增加测量高度。fill-heights 命令利用已测量的数据，通过物理模型推算其他高度的数据，从而构建完整的垂直风廓线。这一功能对于风机轮毂高度的风况评估、风切变分析以及长年代数据的校准都具有重要意义。

fill-heights 命令支持两种工作模式：插值模式和外推模式。插值模式用于计算两个已知测量高度之间的数据值，适用于填补中间层缺失；外推模式则用于计算高于最高测量层的数据值，常用于推算轮毂高度或更高位置的风况。需要特别注意的是，外推仅支持向上外推，不支持向低于最低测量层的方向外推。

在 CleanMast 的历史版本中，外推功能由独立的 extrapolate 命令提供。fill-heights 命令整合了原有 extrapolate 的功能，并在插值算法上进行了增强，提供了基于矢量的风向计算方法，使结果更加符合物理规律。

## 物理原理

### 风速外推的幂律模型

fill-heights 命令采用风速幂律模型进行风速的高度外推和插值。幂律模型是风工程领域广泛使用的经典方法，其基本公式如下：

V2 = V1 × (H2/H1)^α

其中 V1 和 V2 分别代表高度 H1 和 H2 处的风速，α 为风切变指数。风切变指数反映了风速随高度变化的剧烈程度，其取值范围通常在 0.0（中性层结、无切变）到 0.4（强切变）之间，典型值为 0.14 至 0.20。

对于插值计算，命令会在两个相邻测量层之间建立幂律关系。例如，已知 80 米和 100 米高度的风速，需要计算 90 米处的风速时，模型会以 80 米为参考高度，代入 90 米的目标高度进行计算。对于外推计算，则以最高测量层为参考高度，向更高的高度进行推算。

幂律模型假设大气处于中性层结状态，且地形相对平坦。在复杂地形或非中性层结条件下，幂律模型的精度会受到影响，建议结合现场实测数据进行验证。

### 风向的矢量插值方法

风向计算不能简单地使用角度算术平均，这是 fill-heights 命令设计中的重要考量。风向是环形变量，0° 和 360° 表示相同的方向，如果直接对包含 0° 和 359° 的风向取平均值，结果会严重偏离预期值（会得到约 180° 的错误结果）。

为解决这一问题，fill-heights 命令采用矢量平均法进行风向计算。该方法将每个风向角度转换为二维平面上的单位矢量分量，然后对所有分量求和并归一化，最后通过反正切函数得到平均风向。具体计算步骤如下：

首先，将风向角度 θ 转换为水平和垂直分量：

x = cos(θ)

y = sin(θ)

然后对所有采样点的分量分别求和：

X_sum = Σ cos(θi)

Y_sum = Σ sin(θi)

最后，通过反正切函数计算平均风向：

θ_avg = atan2(Y_sum, X_sum)

矢量方法能够正确处理所有角度情况，包括跨越 0°/360° 边界的情况。在高度插值时，命令会对参考高度层的风向数据进行矢量平均，然后同样使用幂律模型进行高度转换。这种方法确保了风向数据的物理一致性。

## 配置文件格式

fill-heights 命令使用 TOML 格式的配置文件来定义处理参数。配置文件主要包含输入数据路径、输出配置、填充目标高度以及物理模型参数等信息。

### 配置文件结构

```toml
# =============================================
# fill-heights 配置文件模板
# =============================================

# 输入数据配置
[input]
# 输入数据文件路径，支持 CSV 或 Parquet 格式
data_file = "projects/my-project/data/processed/mast_data.csv"

# 输出配置
[output]
# 输出文件路径
output_file = "projects/my-project/data/processed/mast_data_filled.csv"
# 输出文件格式，可选值为 "csv" 或 "parquet"
format = "csv"

# 填充高度配置
[heights]
# 目标填充高度列表，单位为米
target_heights = [120, 140, 160]

# 风切变指数配置
[physics]
# 风切变指数，用于幂律外推和插值计算
# 推荐范围：0.14 - 0.20，可根据现场数据调整
shear_exponent = 0.17

# 风向插值方法配置
[wind_direction]
# 是否使用矢量平均法计算风向
use_vector_average = true

# 传感器列配置
[sensor_columns]
# 时间戳列名
timestamp = "timestamp"
# 风速列名（使用 Symbol 格式）
wind_speed = "wind_speed_80m"
# 风向列名（使用 Symbol 格式）
wind_direction = "wind_direction_80m"
# 测量高度列名（单位：米）
height = 80.0
```

### 完整配置示例

以下是一个实际项目中的完整配置文件示例，展示了如何配置 fill-heights 命令处理多高度的测风数据：

```toml
# 项目名称：某风电场测风数据处理
# 创建日期：2025-01-15
# 数据来源：80米测风塔 10分钟平均数据

[input]
data_file = "projects/pn-masts/data/cleaned/pn-mast-01-cleaned.csv"

[output]
output_file = "projects/pn-masts/data/reconstructed/pn-mast-01-filled.csv"
format = "csv"

[heights]
target_heights = [100, 120, 140]

[physics]
shear_exponent = 0.16

[wind_direction]
use_vector_average = true

[sensor_columns]
timestamp = "timestamp"
wind_speed = "wind_speed_80m"
wind_direction = "wind_direction_80m"
height = 80.0
```

### 配置参数说明

**input.data_file**：指定输入数据文件的路径。输入文件应为 CleanMast 处理后的标准化数据，包含时间戳、风速、风向和高度等信息。支持 CSV 和 Parquet 两种格式，Parquet 格式在大数据量情况下具有更好的性能。

**output.output_file**：指定输出文件的路径。输出文件将包含原始数据以及新填充的高度层数据。输出格式由 output.format 参数指定。

**heights.target_heights**：定义需要填充的目标高度列表。所有高度值应为数值类型，单位为米。高度应按升序排列，命令会依次处理每个高度。

**physics.shear_exponent**：设置风切变指数 α 的值。该参数直接影响外推计算的结果，较高的切变指数会产生更剧烈的风速随高度变化。建议根据实测数据校准此参数，或使用项目所在地区的典型值。

**wind_direction.use_vector_average**：布尔值参数，控制风向插值方法。设置为 true 时使用矢量平均法，这是推荐设置；设置为 false 则使用简单的算术平均，可能导致 0°/360° 边界处出现错误结果。

**sensor_columns**：该节定义输入数据中的列名对应关系。timestamp 列应包含有效的日期时间格式；wind_speed 和 wind_direction 列应为数值类型；height 列定义参考测量高度。

## 使用示例

### 生成配置文件

fill-heights 命令提供了 recommend 子命令用于生成配置文件模板。使用 recommend 子命令时，需要指定项目路径和目标填充高度列表：

```bash
# 生成填充 120m、140m、160m 高度的配置文件
uv run cleanmast recommend fill-heights projects/my-project -h 120,140,160

# 生成填充单个高度的配置文件
uv run cleanmast recommend fill-heights projects/my-project -h 100
```

recommend 子命令会在指定的项目目录下创建 fill-heights 配置文件，文件名格式为 fill-heights-reconstruct-meso.toml。用户可以根据实际需求修改配置参数。

### 执行高度填充

生成并修改配置文件后，使用 fill-heights 命令执行高度填充操作：

```bash
# 执行高度填充
uv run cleanmast fill-heights projects/my-project/fill-heights-reconstruct-meso.toml

# 指定配置文件路径执行
uv run cleanmast fill-heights /path/to/fill-heights-config.toml
```

命令执行过程中会在控制台输出处理进度和关键信息，包括输入数据量、目标高度列表、计算结果摘要等。处理完成后，输出文件将保存在配置文件中指定的位置。

### 批量处理多个配置

对于包含多个测风塔的项目，可以分别处理每个塔的数据：

```bash
# 处理测风塔 01
uv run cleanmast fill-heights projects/pn-masts/config/fill-heights-tower-01.toml

# 处理测风塔 02
uv run cleanmast fill-heights projects/pn-masts/config/fill-heights-tower-02.toml
```

也可以使用 shell 脚本实现批量处理：

```bash
#!/bin/bash
# 批量处理所有 fill-heights 配置

for config in projects/pn-masts/config/fill-heights-*.toml; do
    echo "Processing: $config"
    uv run cleanmast fill-heights "$config"
done
```

## 限制条件

### 传感器统计类型限制

fill-heights 命令目前仅支持 avg（平均）类型的传感器数据。这一限制源于幂律模型和矢量平均法的物理假设。平均风速和平均风向反映了特定时间段内的统计特征，适合使用对数风廓线或幂律风廓线进行外推。

对于其他统计类型的传感器（如最大值、最小值、标准差等），物理模型的外推假设不再成立。这些统计量的高度变化关系复杂，不能简单地使用幂律模型描述。如果项目中有其他类型的传感器数据需要处理，建议单独进行分析，或联系开发团队了解后续版本的支持计划。

### 最低测量层限制

fill-heights 命令不支持向低于最低测量层的方向外推或插值。这一限制是物理上的硬性约束。风速随高度变化的规律是从地面开始的边界层效应，低于最低测量高度的区域缺乏有效的物理模型支撑。

例如，如果测风塔的最低传感器高度为 40 米，则不能使用 fill-heights 命令计算 30 米或 20 米处的风速。这种情况下，需要在实际项目中部署更低高度的传感器，或使用经验模型进行估算但需明确标注为非实测数据。

### 风切变边界警告

当计算得到的风切变指数超出合理范围时，fill-heights 命令会输出 "shear out of bounds" 警告信息。正常的大气边界层条件下，风切变指数通常在 0.0 至 0.4 之间。超出此范围可能由以下原因导致：

传感器故障或数据质量问题是最常见的原因。如果某一高度层的风速数据存在明显异常，幂律模型计算出的切变指数会偏离正常范围。数据缺失也可能导致计算结果异常，特别是当某一高度层有大量缺失值时。极端天气条件（如强对流、锋面过境）期间，风廓线可能呈现非常规形态，此时的切变指数也可能超出正常范围。

收到此类警告时，建议检查原始数据的质量，确认传感器工作状态，并在必要时进行数据清洗或排除异常时段。

### 最大插值距离建议

为保证插值结果的可靠性，建议相邻测量层之间的垂直距离不超过 40 米。这一建议基于幂律模型的统计特性。距离过大时，中间高度的风况可能受到更多不确定因素的影响，幂律模型的误差也会累积放大。

对于垂直测风高度跨度较大的项目（如 80 米到 160 米之间仅有 80 米一层传感器），建议采用以下策略：要么增加中间测量层，要么在配置文件中将目标高度分批处理，并对中间结果进行合理性验证。

## 常见问题

### 为什么我的高度被跳过了？

目标高度被跳过可能有多种原因。首先，请确认目标高度不在已有测量高度列表中。如果目标高度与现有测量高度完全相同，命令会自动识别并跳过，因为该层数据已存在。

其次，检查目标高度是否低于最低测量层。fill-heights 命令不会向低于参考高度的方向处理任何数据。如果配置文件中指定了此类高度，命令会输出警告并跳过处理。

第三，检查数据文件中的列名配置是否正确。如果 sensor_columns 节中的列名与实际数据文件中的列名不匹配，命令可能无法正确读取数据，此时整个处理过程可能失败而不产生任何输出。

最后，请查看命令执行时的控制台输出信息。fill-heights 命令会在处理每个高度前输出当前状态，如果某个高度被跳过或出现问题，通常会有相应的提示信息。

### "shear out of bounds" 警告的含义是什么？

"shear out of bounds" 警告表示根据输入数据计算得到的风切变指数超出了预设的合理范围（通常为 0.0 至 0.4）。这一警告是数据质量检查机制的一部分，用于提醒用户关注可能存在问题的数据时段。

出现此警告时，建议按以下步骤排查：

第一步，检查原始数据的完整性。确认被警告时段内的所有测量层数据都存在，没有大面积缺失。数据缺失会导致计算结果异常。

第二步，检查传感器工作状态。被警告时段内的传感器可能存在故障，如风向标卡死、风速计失准等，这些问题会导致异常的计算结果。

第三步，考虑天气因素的影响。被警告时段可能处于极端天气条件之下，如强对流、雷暴、锋面过境等，此时的风廓线确实可能呈现非常规形态。

第四步，如果确认数据无误且天气条件正常，可以考虑在后续分析中排除这些时段，或者使用更稳健的切变指数估计方法。

### 如何处理 0°/360° 边界的风向数据？

fill-heights 命令内置的矢量平均法已经正确处理了 0°/360° 边界问题。用户无需在数据预处理阶段进行任何特殊操作。

矢量平均法的核心优势在于将角度转换为正弦和余弦分量后进行平均。由于正弦和余弦函数本身是周期性的，能够自然地处理角度的环形特性。例如，0° 和 360° 转换为矢量后完全相同（x=1, y=0），平均结果自然也是 0° 或 360°。

对于包含多个风向样本的数据集，矢量方法能够正确处理跨越边界的情况。例如，如果风向样本为 355°、0° 和 5°，矢量平均会正确计算出北风（0° 左右）的平均值，而不是错误的西风或西南风。

如果用户在外部工具中自行处理风向数据，务必使用矢量平均或等效方法，不要使用简单的算术平均。算术平均在处理跨越 0°/360° 边界的数据时会产生约 180° 的系统误差。

### 可以填充低于最低测量层的高度吗？

不可以。fill-heights 命令的设计理念是基于已有的实测数据进行高度方向的扩展，不支持向低于最低测量层的方向外推。这一限制不仅是软件的设计选择，更是物理规律的约束。

低于最低测量层的区域属于近地面层，该层的风速变化受到地面粗糙度、地形效应、热力层结等多重因素的复杂影响，不能简单地用幂律模型描述。如果项目需要更低高度的风况数据，必须在实际项目中部署相应高度的传感器进行实测。

对于需要进行近地面层研究的项目，建议单独分析实测数据，并可以考虑使用对数风廓线模型或更高阶的大气边界层模型进行估算，但这些方法超出 fill-heights 命令的功能范围。

### 外推高度有没有最大限制？

fill-heights 命令本身没有硬性的外推高度上限，但基于物理合理性和数据质量的考虑，建议外推高度不超过最高测量层的 1.5 倍。例如，如果最高测量层为 100 米，则外推至 150 米以内的高度是相对可靠的。

超出此范围时，幂律模型的误差会显著增大。一方面，参考高度的数据噪声会在外推过程中被放大；另一方面，大气边界层的物理特性在更高处可能发生变化（如进入自由大气层），幂律模型的假设不再成立。

对于需要评估很高位置风况的项目（如 150 米以上的轮毂高度或更高），建议优先考虑以下方案：使用长年代数据与测风塔数据的相关性进行间接校准、使用中尺度气象模式的再分析数据、或者在现场增设更高位置的测风设备（如激光雷达或测风塔）。
