# CleanMast 文档编写规范

## 概述

本文档定义了 CleanMast 项目的文档编写标准，确保文档的一致性、准确性和可维护性。

## 文档结构原则

### 1. 模块化组织
- **单一职责**: 每个文档文件专注于一个特定主题
- **分级结构**: 使用目录层次反映功能层次
- **命名一致**: 文件名与功能名称保持一致

### 2. 标准目录结构
```
docs/
├── user/                    # 用户文档
│   ├── commands/
│   │   ├── recommend/       # recommend 命令系列
│   │   ├── process/         # process 命令系列
│   │   └── process-steps.md   # process steps 命令
│   └── configuration/
│       └── config-files.md  # 配置文件参考
└── development/             # 开发者文档
    └── README.md
```

## 配置示例规范

### 1. 基于实际项目
- **必须使用** `projects/pn-3masts/` 中的真实配置作为示例
- **禁止创造** 理论性或虚构的配置示例
- **保持一致** 所有示例使用相同的项目结构

### 2. 配置文档格式
```toml
# 配置文件说明
# 基于实际项目结构: projects/pn-3masts/config-name.toml

# 主要配置段
[[masts]]
name = "pn-002824"  # 使用实际名称
    [masts.input]
    data = "./path/file.csv"  # 使用实际路径结构
    sensors = "./path/file.yaml"
```

## 技术参考规范

### 1. 代码路径引用
- **格式**: `src/ModuleName/FileName.jl`
- **准确性**: 确保路径真实存在
- **一致性**: 使用相同的引用格式

### 2. 实现位置标注
```markdown
## 实现位置
**核心实现**: `src/MainModule/CommandFile.jl`
**核心算法**: `src/MainModule/Core.jl`
**辅助模块**: `src/HelperModule/SpecificFile.jl`
```

### 3. 类型系统引用
- **配置类型**: `src/Types/ConfigNameConfig.jl`
- **数据类型**: `src/Types/DataTypeName.jl`
- **结果类型**: `src/Types/ResultTypeName.jl`

## 交叉引用规范

### 1. 内部链接格式
- **相对路径**: `[链接文本](../relative/path.md)`
- **准确性检查**: 确保所有链接指向存在的文件
- **描述性文本**: 使用清晰的链接描述

### 2. 标准交叉引用模式
```markdown
## 相关文件

```

### 3. 工作流链接
- **前置步骤**: 链接到必需的前置命令
- **后续步骤**: 链接到推荐的下一步操作
- **相关功能**: 链接到相关的命令或配置

## 内容质量标准

### 1. 准确性要求
- **代码对应**: 文档必须与实际代码实现一致
- **示例真实**: 所有示例基于真实项目数据
- **路径正确**: 所有文件路径和引用准确无误

### 2. 完整性要求
- **功能覆盖**: 涵盖命令的所有主要功能
- **参数说明**: 详细说明所有重要参数
- **输出描述**: 明确说明输出文件和格式

### 3. 可用性要求
- **操作指导**: 提供清晰的使用步骤
- **错误预防**: 包含注意事项和最佳实践
- **问题解决**: 提供常见问题的解决方案

## 语言风格指南

### 1. 术语一致性
- **命令名称**: 保持与代码中完全一致
- **技术术语**: 统一使用约定的中文术语
- **变量名称**: 保持英文原名，不翻译

### 2. 描述风格
- **简洁明确**: 避免冗长的描述
- **实用导向**: 重点关注如何使用
- **结构化**: 使用列表和层次结构组织信息

### 3. 代码示例
- **格式规范**: 使用正确的 markdown 代码块
- **注释适度**: 添加必要但不冗余的注释
- **完整可用**: 确保示例代码可以直接使用

## 维护更新流程

### 1. 版本同步
- **代码更新**: 代码变更时及时更新文档
- **配置变更**: 配置格式变化时更新示例
- **功能迭代**: 新功能添加时扩展文档

### 2. 质量检查
- **链接验证**: 定期检查内部链接有效性
- **示例测试**: 验证配置示例的正确性
- **内容审核**: 确保文档与实际功能匹配

### 3. 持续改进
- **用户反馈**: 根据使用反馈改进文档
- **最佳实践**: 更新和完善编写标准
- **工具支持**: 开发自动化文档检查工具

## 禁止事项

### 1. 内容禁止
- ❌ **创造虚假示例**: 不使用不存在的配置或数据
- ❌ **过时信息**: 不保留已废弃的功能说明
- ❌ **理论描述**: 避免纯理论性的技术解释

### 2. 格式禁止
- ❌ **断开链接**: 不使用指向不存在文件的链接
- ❌ **不一致命名**: 避免同一概念的多种表述
- ❌ **格式混乱**: 不使用不规范的 markdown 格式

### 3. 维护禁止
- ❌ **独立维护**: 不在没有验证的情况下更新文档
- ❌ **批量修改**: 避免未经测试的大批量文档修改
- ❌ **忽略依赖**: 不忽略文档间的交叉引用关系
